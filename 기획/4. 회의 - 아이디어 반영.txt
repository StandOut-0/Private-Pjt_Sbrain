[Second Brain Frontend 리뉴얼 공통 작업 규칙]

현재 Second Brain 프로젝트는 Frontend 기능이 이미 구현되어 있으며 정상 동작하고 있다.
이번 작업의 목적은 기존 기능을 수정하거나 재설계하는 것이 아니라 UI/UX를 개선하는 것.

반드시 지킬 것
1. 기존에 정상 동작하는 기능의 로직을 변경하지 않는다.
2. 기존 API 호출, URL, Django View, Form, JavaScript 이벤트, DB 구조를 임의로 변경하지 않는다.
3. 기존 기능을 삭제하지 않는다.
4. 기존 화면의 데이터 흐름을 변경하지 않는다.
5. 기존 기능과 충돌할 가능성이 있는 코드는 작성하지 않는다.
6. 필요한 경우 기존 HTML 구조를 최대한 유지하고 CSS 또는 최소한의 UI 구조만 수정한다.
7. 새로운 기능이 필요하더라도 우선 UI 표현만 추가하고 실제 기능 구현은 별도 작업으로 분리한다.
8. 기존 JavaScript를 수정해야 하는 경우 수정 전 동작을 반드시 확인하고 최소 범위만 변경한다.
9. 기존 Bootstrap 및 현재 프로젝트의 CSS 구조를 우선 재사용한다.
10. 새로운 라이브러리를 임의로 추가하지 않는다.
11. 기존 반응형 구조를 깨뜨리지 않는다.
12. 작업 전에 반드시 현재 코드를 확인하고 기존 기능의 동작 구조를 파악한다.
13. 작업 후 기존 기능이 그대로 동작하는지 확인한다.
14. 작업 범위를 임의로 확대하지 않는다.
15. 이번 작업에서 요청하지 않은 페이지나 기능은 수정하지 않는다.

작업 방식
작업 시작 전:
수정 대상 파일 확인
관련 Template 확인
관련 CSS 확인
관련 JavaScript 확인
기존 기능과의 연결 관계 확인
그 다음 UI 변경을 최소 범위로 적용한다.

완료 기준
기존 기능 정상 동작
기존 URL 정상 동작
기존 API 정상 동작
기존 버튼/폼 정상 동작
기존 데이터 출력 정상 동작
요청한 UI 변경만 적용
다른 화면에 의도하지 않은 디자인 변경이 발생하지 않음
작업 완료 후 반드시 다음 내용을 간단하게 보고한다.

1. 수정한 파일
2. 변경한 UI
3. 기존 기능에 영향을 주지 않기 위해 취한 조치
4. 테스트한 기능
5. 추가로 수정하면 좋지만 이번 작업에서는 건드리지 않은 부분

작업 01 — Dashboard Notification UI 추가
Second Brain Dashboard에 사용자 Notification 영역을 추가한다.

목적
사용자가 프로젝트 작업 완료, Agent 작업 완료, 오류 등의 상태를 놓치지 않도록 Dashboard에서 알림을 확인할 수 있도록 한다.

요구사항
Dashboard 우측 상단의 사용자 영역 근처에 Notification UI를 추가한다.
🔔 3 알림 버튼을 클릭하면 Popup 또는 Dropdown 형태로 최근 알림을 보여준다.

알림 예시:
프로젝트 작업 완료
Agent 작업 완료
결과물 생성 완료
Agent 실행 오류
프로젝트 작업 중단
검토가 필요한 결과 발생
각 알림에는 가능하면 다음 정보를 표시한다.

알림 유형
간단한 메시지
발생 시간
관련 Project
읽음 / 안 읽음 상태

시간은 다음과 같이 친숙하게 표현한다.
방금 전
3분 전
1시간 전
어제

중요
실제 Notification DB/API를 새로 구현하지 않는다.
현재 Frontend 구조에서 안전하게 UI를 먼저 구현한다.
기존 데이터 구조로 구현하기 어려운 부분은 Mock 또는 정적 데이터로 표현해도 된다.
단, 실제 기존 기능과 연결되어 있는 코드는 수정하지 않는다.

UI 방향
Notification Dropdown은 너무 큰 영역을 차지하지 않도록 한다.
안 읽은 알림에는 Badge를 사용한다.
오류 알림은 시각적으로 구분한다.

완료 기준
Dashboard의 기존 기능은 그대로 동작해야 한다.
Notification UI만 추가되어야 한다.







작업 02 — Dashboard 새 프로젝트 버튼 추가
Dashboard 우측 상단에 사용자가 빠르게 새로운 프로젝트를 생성할 수 있도록 [+ 새 프로젝트] 버튼을 추가한다.

위치
Header 또는 Dashboard Content 상단 우측.

예:
최근 프로젝트                         [+ 새 프로젝트]

요구사항
기존 Project Create 기능이 있다면 반드시 기존 기능을 재사용한다.
새로운 Project 생성 로직을 만들지 않는다.
버튼 클릭 시 기존 Project Create 화면 또는 기존 Project Create Modal로 이동한다.

디자인
Bootstrap Button 스타일을 사용한다.
Dashboard의 기존 디자인과 자연스럽게 연결한다.
사용자가 첫 화면에서 프로젝트 생성 기능을 쉽게 발견할 수 있도록 강조한다.

중요
Project 생성 Backend/API/View/Form은 절대 수정하지 않는다.
기존 Project Create URL을 그대로 사용한다.

완료 기준
Dashboard에서 버튼이 정상 표시된다.
버튼 클릭 시 기존 프로젝트 생성 기능으로 정상 이동한다.
기존 Project 기능에는 영향이 없어야 한다.









작업 03 — 프로젝트 및 결과물 최근 활동 시간 UI
Second Brain의 프로젝트 카드와 결과물 목록에 최근 활동 시간을 표시한다.

표시 방식
정확한 timestamp 대신 사용자 친화적인 상대시간을 사용한다.
예:
방금 전
3분 전
12분 전
2시간 전
어제
3일 전

적용 대상
가능한 범위에서 다음 영역에 적용한다.

Project Card
Project Detail
Artifact / Result 목록
최근 생성된 문서
최근 수정된 문서

중요
기존 timestamp 데이터가 있다면 그것을 사용한다.
Backend의 timestamp 구조를 변경하지 않는다.
timestamp 데이터가 현재 Frontend에 존재하지 않는 경우 Backend/API를 이번 작업에서 수정하지 않는다.
그 경우 UI 구조만 준비한다.

완료 기준
시간 표시가 기존 카드/목록 디자인을 방해하지 않는다.
기존 Project 및 Artifact 기능은 변경하지 않는다.






작업 04 — 결과물 문서관리 지시사항 UI 개선
Second Brain의 결과물 문서 관리 화면에서 사용자가 문서에 대한 지시사항을 쉽게 이해하고 작성할 수 있도록 UI를 개선한다.

문제
현재 전체 공통 지시사항과 프로젝트별 지시사항이 함께 존재할 경우 사용자가 어느 지시사항을 작성해야 하는지 혼동할 수 있다.

목표
사용자가 다음 두 영역의 차이를 직관적으로 이해할 수 있도록 한다.
1. 전체 공통 지시사항
2. 프로젝트별 지시사항

UI 방향
두 영역을 단순히 나열하지 말고 명확한 설명을 추가한다.

예:
[전체 공통 지시사항]
모든 프로젝트와 Agent 작업에 공통으로 적용됩니다.

[프로젝트별 지시사항]
현재 선택한 프로젝트에서만 적용됩니다.
가능하면 Icon, Tooltip, 설명 문구를 사용한다.

추천 UI
전체 공통
🌐 모든 프로젝트에 적용

프로젝트별
📁 현재 프로젝트에만 적용

중요
기존 지시사항 저장/수정/삭제 기능은 변경하지 않는다.
이번 작업은 UI/UX 개선만 수행한다.
DB 구조나 API를 변경하지 않는다.

완료 기준
사용자가 화면을 처음 봤을 때 두 지시사항의 차이를 이해할 수 있어야 한다.




작업 05 — 사용자 가이드 UI 준비
Second Brain 사용자가 서비스를 쉽게 이해할 수 있도록 User Guide 진입 UI를 개선한다.

목표
텍스트 중심의 설명보다 Icon, Image, Screenshot 중심으로 사용자가 쉽게 이해할 수 있는 구조를 만든다.

UI 요구사항
Settings 또는 Help 영역에 다음과 같은 메뉴를 추가한다.

📖 사용자 가이드
클릭하면 사용자 가이드 PDF를 열 수 있도록 한다.

PDF
PDF 자체 제작은 이번 작업의 범위에서 제외한다.
Frontend에서는 다음 기능만 준비한다.
사용자 가이드 버튼
PDF 열기
새 창 또는 Viewer에서 PDF 표시
향후 실제 프로젝트가 완성된 후 실제 화면 Screenshot을 넣어 PDF를 제작할 예정이다.

중요
PDF가 존재하지 않는 현재 환경에서는 broken link가 발생하지 않도록 처리한다.
기존 Settings 기능은 변경하지 않는다.






작업 06 — Demo Login 연계 화면 Tour UI
Second Brain에 처음 접속한 사용자가 주요 기능을 쉽게 이해할 수 있도록 화면 Tour UI를 추가한다.

목표
Demo Login으로 체험한 사용자가 서비스의 주요 기능을 자연스럽게 둘러볼 수 있도록 한다.

UI 방식
Tooltip / Popover 기반의 단계별 Tour를 사용한다.

예:
Step 1
👋 Dashboard입니다.
Step 2
📁 여기에서 프로젝트를 관리할 수 있습니다.
Step 3
🤖 프로젝트 안에서 AI Agent에게 작업을 요청할 수 있습니다.
Step 4
📄 생성된 결과물은 여기에서 확인할 수 있습니다.
Step 5
🔔 작업 완료 및 오류 알림을 확인할 수 있습니다.

중요
기존 Login 인증 로직은 수정하지 않는다.
Demo Login 기능도 수정하지 않는다.
화면 Tour는 Frontend UI 수준에서만 구현한다.
Tour를 종료해도 기존 서비스 사용에 문제가 없어야 한다.

완료 기준
Demo Login 후 Dashboard에서 Tour를 시작할 수 있다.
Tour Skip / Next / Previous / Finish 기능을 제공한다.

UI

[사용자 초대]

초대 대상
초대 링크
사용자 가이드 PDF 링크
링크 복사
이메일로 보내기
공유하기

중요

우선 Frontend에서 사용자가 어떤 정보를 공유하는지 이해할 수 있도록 UI를 구성한다.
실제 초대 시스템은 별도 작업으로 분리한다.






작업 09 — 기본 Safety Policy UI

Second Brain에서 생성형 AI 사용 시 기본적으로 제한해야 할 요청 유형을 안내하는 Safety Policy UI를 추가한다.

제한 대상 예시

음란물
폭력적 콘텐츠
불법 행위 지원
명백한 위험 행위

UI
Settings 또는 사용자 가이드에서 다음과 같이 확인할 수 있도록 한다.

🛡️ AI 사용 정책
Second Brain은 안전한 서비스 이용을 위해 일부 요청을 제한할 수 있습니다.

중요
실제 LLM Safety Filter 구현은 이번 작업에서 하지 않는다.
정책 문서 및 UI 표현만 구현한다.
Backend, Agent Prompt, LLM 호출 로직을 수정하지 않는다.
향후 Safety Policy를 실제 Agent 시스템에 적용할 수 있도록 확장 가능한 UI 구조만 만든다.












작업 10 — Agent 작업 강제 중단 UI
프로젝트 Chat 또는 Agent 실행 화면에 사용자가 현재 진행 중인 작업을 중단할 수 있는 UI를 추가한다.

UI
Agent 실행 중:
[● Agent 실행 중...]        [■ 작업 중단]
버튼을 표시한다.
중단 후
사용자에게 다음 메시지를 보여준다.
"현재 Agent 작업을 중단했습니다."
그리고 선택지를 제공한다.
[처음부터 다시 만들기]
[채팅 계속하기]

중요
이번 작업에서는 실제 Agent 실행 중단 로직을 변경하지 않는다.
기존 Agent 실행 API가 이미 존재하는 경우 해당 API를 확인한 후 연결 가능성을 판단한다.
API가 없다면 버튼 UI만 구현하고 실제 중단 기능은 구현하지 않는다.
기존 Agent 실행 프로세스를 임의로 수정하지 않는다.
토큰 절약 등의 실제 효과는 Backend 작업에서 별도로 구현한다.

작업 17 — Chat 시작 화면 Animation 개선
Project Chat 최초 진입 시 표시되는 AI 시작 화면을 개선한다.

목표
딱딱한 Chatbot보다 Second Brain의 AI 업무 파트너라는 느낌을 줄 수 있도록 한다.

방향
귀엽고 가벼운 GIF 또는 Animation을 사용한다.
예:
🤖 AI가 준비 중입니다.
"프로젝트 내용을 살펴보고 있어요."

중요
외부 이미지/라이브러리를 임의로 추가하지 않는다.
현재 프로젝트에서 사용 가능한 Asset 구조를 우선 확인한다.
Animation이 성능에 영향을 주지 않도록 한다.
Chat 기능 자체는 변경하지 않는다.

Evaluation Agent의 실제 점수 계산 방식은 절대 변경하지 않는다.

작업 23 — Wizard Tooltip 고도화
Project 작업 Wizard의 각 단계에 Tooltip을 추가한다.

목적
사용자가 각 Agent/단계의 역할을 별도 문서를 읽지 않고 이해할 수 있도록 한다.

예시
Planning
"사용자 요구사항을 분석하고 PRD를 작성합니다."

Engineering
"기획 결과를 기반으로 Frontend와 Backend를 구현합니다."

Reflection
"생성된 결과를 검증하고 개선점을 제안합니다."

원칙
Tooltip은 짧고 직관적으로 작성한다.
너무 많은 정보를 넣지 않는다.
필요하면 "자세히 보기" 형태로 확장 가능하도록 한다.
기존 Pipeline 로직은 수정하지 않는다.












작업 24 — Global Error Header Alert

Second Brain 전체 화면에서 중요한 Agent/Task 오류를 사용자가 놓치지 않도록 Header 상단에 고정 Alert UI를 추가한다.
예시
┌─────────────────────────────────────────────────────────────┐
⚠️ Project 01의 Agent 실행에 실패했습니다. [확인하기] [닫기]
└─────────────────────────────────────────────────────────────┘

요구사항
Header 상단 고정
오류 발생 시 표시
확인하기 버튼
닫기 버튼
관련 Project / Task로 이동할 수 있는 구조

중요
실제 오류 감지 Backend는 변경하지 않는다.
현재 Frontend에서 확인 가능한 오류 상태를 우선 활용한다.
오류 상태가 없는 화면에서는 UI Component만 구현한다.













작업 25 — Agent 결과 처음부터 다시 만들기 UI
Reflection 결과가 만족스럽지 않은 경우 사용자가 처음부터 작업을 다시 실행할 수 있도록 UI를 추가한다.
버튼
[처음부터 다시 만들기]

버튼 클릭 시 확인 Modal:
"현재 결과를 기반으로 처음부터 다시 작업하시겠습니까?"

경고:
"기존 결과가 새로운 실행 결과로 대체될 수 있습니다."

[취소]
[다시 만들기]

중요
실제 재실행 API가 이미 존재하는 경우에만 연결한다.
존재하지 않는 경우 UI만 구현한다.
기존 결과물을 삭제하거나 덮어쓰는 Backend 로직은 이번 작업에서 구현하지 않는다.
















작업 26 — Chat 응답 Tab UI
Chat 응답이 길어지는 문제를 개선하기 위해 답변 내용을 Tab 형태로 구성할 수 있는 UI를 추가한다.
예시

[요약] [결과물] [근거] [검증]
또는
[기획 결과]
[생성 파일]
[검증 결과]

목적
긴 AI 응답을 한 화면에 모두 출력하지 않고 사용자가 필요한 영역만 선택해서 볼 수 있도록 한다.
중요
Chat 메시지 저장 구조를 변경하지 않는다.
LLM 응답 생성 방식도 변경하지 않는다.
기존 메시지를 Tab UI 안에 표시하는 Frontend 작업으로 제한한다.
기존 Chat Scroll 및 메시지 기능을 깨뜨리지 않는다.
