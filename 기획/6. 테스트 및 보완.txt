3. 테스트 및 검사 결과

- Django 전체 테스트: Reflection 보완 후 64개 발견, 62개 통과, Planning/Reflection Ollama live test 2개 기본 생략 (`front/.venv/Scripts/python.exe manage.py test --verbosity 1`)
- 실제 로컬 LLM 종단 테스트: Planning 1개 통과 (`RUN_LOCAL_LLM_TEST=1`, `gemma4:latest`, 기존 71초) 및 Reflection 1개 통과 (동일 설정, 160초). Django API와 Worker/Artifact에 이어 실제 모델이 기준별 Reflection 보고서를 생성하고 비 mock 평가로 저장하는 것까지 확인했다.
- Django system check: 통과 (`manage.py check`, issues 0)
- migration drift: 통과 (`manage.py makemigrations --check --dry-run`, 변경 없음)
- React production build: 통과 (`front/react`에서 `npm run build`, Vite 6.4.1)
- Git whitespace 검사: 통과 (`git diff --check`)
- 기존 종단 간 테스트는 프로젝트 생성 → 실행 → Artifact 저장·다운로드 → Reflection 저장/화면 표시 → 소유권 차단을 검증한다. 추가 Reflection 테스트는 유효하지 않은 모델 결과는 저장하지 않고, Ollama 장애는 재시도 가능한 오류로 반환하는 것을 확인한다.
- 추가 회귀 테스트는 평가 기준 Admin/API 권한, 잘못된 기준 입력, Artifact 저장 실패 종료, 실행 중 취소 멱등성을 검증한다.
- Ollama HTTP 응답 해석, 비용 0 기록, token 수 기록, 서비스 연결 실패 및 cloud 모델 차단을 회귀 테스트로 검증했다.

4. 확인한 현재 제한 및 후속 작업

- 브라우저 실화면 수동 확인은 하지 않았다. 주요 페이지의 반응형 배치, 이미지/아이콘 로딩, 대화형 동작은 별도 브라우저 QA가 필요하다.
- Planning과 Reflection은 기본으로 PC의 Ollama `gemma4:latest`에서 LLM 추론을 한다. Planning의 `fake` provider는 테스트 용도로 남아 있다. Reflection은 JSON Schema 강제 출력과 기준 key·점수·근거 검증을 거치며, 모델 장애 시 mock 점수를 대신 만들지 않고 실패를 반환한다.
- 로컬 Ollama 호출에는 provider API 사용료가 없지만 하드웨어 속도·메모리·전력 사용은 발생한다. 실제 품질은 사용자 입력과 컴퓨터 환경에 따라 달라진다.
- Hosted free API는 계정별 quota·정책이 바뀔 수 있다. 이번 기본 설정은 hosted API를 호출하지 않는다. 무료 선택지 비교는 `기획/5. 무료 LLM 모델 서치.txt`를 참고한다.
- 실행 중 취소는 Provider 응답이 돌아온 시점에 반영된다. 현재 외부 Provider가 없으며, 향후 adapter는 호출 자체의 timeout/취소를 구현해야 한다.
- 개발 DB는 SQLite이고 Worker supervisor, 내구성 있는 작업 큐, 백업·복구·보존 자동화는 구성되지 않았다. 다중 Worker 운영 및 production 배포는 별도 검증/구성이 필요하다.
- Ollama live integration test는 `RUN_LOCAL_LLM_TEST=1`일 때만 수행한다. 실제 테스트에서 LLM이 완성된 PRD를 내는 데 71초 걸렸다. 기본 Django 회귀 테스트는 네트워크 없이 Fake provider 또는 mock HTTP 응답을 사용한다.
- Ollama 서비스 중지, 모델 미설치, timeout은 구조화된 실패로 표시된다. Hosted provider 연결은 적용하지 않았다.
- 위 제한은 Day 18·20 보고서와 `docs/operations/security-checklist.md`의 운영 차단 항목과 일치하며 이번 변경에서 운영 완료로 표시하지 않았다.

**종합 판정:** Reflection은 로컬 모델 평가로 구현했고 모델이 없거나 응답이 잘못되면 mock 점수를 내지 않고 오류로 반환한다. 15-2의 평가 게이트는 코드·실제 모델 검증 기준으로 충족한다. 브라우저 시각/사용자 인수는 UI tool 문제로 아직 완료하지 못했으며, SQLite 기반 운영·durable worker·백업 자동화도 운영 배포 차단 항목으로 남는다. 전체 사용자의 MVP 최종 인수는 실제 브라우저 검수 뒤 승인해야 한다.
